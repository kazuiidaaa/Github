# 画面デザインの規則（Issue #122）

画面の見た目を Apple の画面に近づけつつ、業務での長時間使用に耐えることを目的とする。

## 色
- 青・橙・灰を基調とし、赤と緑の対比に頼らない。
- 文字は背景に対し 4.5 以上、枠線は 3 以上の対比（WCAG AA）。明色・暗色の両方で確認済み。
- 色の定義は `app/globals.css` の `@theme`（明色）と `:root[data-theme="dark"]`（暗色）に集約する。
- 既存画面が使う Tailwind の色名は、次のとおり読み替えている（各画面の置き換えは Issue #123）。
  - `slate` / `white`：灰（Apple の灰）
  - `red`：橙系（エラー・要対応）
  - `amber` / `yellow`：黄土系（注意）
  - `green`：青緑系（完了）
  - `blue`：青（情報・操作）
- 新しい画面では、色名を直接指定せず、`accent`、`line-strong`、共通部品（`components/ui.tsx`）を使う。

## 状態の表示
- 色だけに頼らず、文字と図形を併記する（`Badge`）。
  - 完了＝丸に印、注意＝三角、要対応＝ひし形、未了＝破線の丸、情報＝丸に点。
- 絵文字は使わない。

## 字の太さ
- 本文 500、見出し・項目名・ボタン 700。読み込む太さは 500 / 600 / 700。

## 明暗の切り替え
- 初期は OS の設定に従い、ヘッダーの「表示」ボタンで自動・明るい・暗いを切り替える。
- 選択は `localStorage`（キー `theme`）に保存する。描画前に `data-theme` を決めるため、表示はちらつかない。
- 暗色は純粋な黒ではなく濃い灰（背景 #1d1d1f、字 #f5f5f7）。

## 動き
- 時間は 0.15〜0.3 秒、曲線は `--ease-apple`。
- 画面の切り替え（`PageTransition`）、押したときの縮み、背景のぼかし（ヘッダー）、一覧の順次表示（`anim-stagger`）、ダイアログの表示（`anim-pop-in`）。
- OS で「視差効果を減らす」が設定されている場合は、動きを止める。

## 各画面への適用（Issue #123）
- カードは角丸を大きく（`rounded-2xl`）、ボタンは丸形、入力欄の枠は `border-line-strong` に統一した。
- 主ボタンは `bg-accent`。選択中の表示（件数カード、タブ、切り替え）も `accent` を使う。
- ダイアログは背景をぼかし、本体を拡大しながら表示する（`anim-fade-in` / `anim-pop-in`）。
- 一覧・件数カードは `anim-stagger` で順に表示する。
- 書類のプレビュー（紙の見た目）は、暗色表示でも白地に黒字のままにする。`paper` クラスで色の読み替えを打ち消している。

## トップページ（Issue #126）
- `/` はホーム画面。件数（確認待ち・書類待ちなど）、在留期限が近い案件、最近更新した案件を表示する。件数は、案件一覧の該当する絞り込みへ移動する。
- ロゴはホームへ移動する。ヘッダーに「ホーム」「案件一覧」を置き、現在地は下線と `aria-current` で示す（色だけに頼らない）。
- ログイン後の移動先はホーム。案件一覧（`/cases`）の仕様は変更しない。

## 操作完了の通知（Issue #140）
- 保存・作成・削除・アップロードの結果は、画面下部の通知（トースト、`components/Toast.tsx`）で知らせる。`app/layout.tsx` に1か所だけ置き、画面遷移をまたいで表示する。
- 成功は 5 秒で自動的に消え（`role="status"`）、失敗は閉じるまで消えない（`role="alert"`）。どちらも「×」ボタンまたは Esc キーで閉じられる。種類は色だけでなく、図形（丸に印・ひし形）でも示す。
- 文言に、氏名・案件名などの個人情報を含めない。
- フォーム内の保存表示は `role="status"` を付け、文言は「保存しました」に統一する。ただし「下書きを保存しました」のように状態の違いが重要なものは維持する。

## 書体（Issue #216）
- 画面の書体は、Apple 端末ではシステム書体にする。英数字は San Francisco（`-apple-system`）、日本語はヒラギノ角ゴ ProN、予備はヒラギノ角ゴシック（`Hiragino Sans`）。
- Apple 以外の端末では、Inter（英数字）と Noto Sans JP（日本語）を使う。どちらも `next/font` で、500・600・700 のみを読み込む。
- Apple の書体は、利用許諾の都合で Web へ同梱できない。端末に入っているものを名前で指定する。
- 先に書いた書体が端末にある場合、ブラウザーは後ろの書体を取得しない。`next/font` の事前読み込み（`preload`）は止めている。
- 等幅（`--font-mono`）も、同じ指定を使う。定義は `app/globals.css` の `--font-sans`。
- ヒラギノ角ゴ ProN の太さは W3・W6 の2種類のため、本文の 500 が細く見える場合は、`"Hiragino Sans"` を `"Hiragino Kaku Gothic ProN"` より先に書く。
- 書類のプレビュー（`paper`）、PDF、Word、Excel の書体は変更しない。`paper` は Noto Sans JP を明示して指定している。
