方針は `docs/phase11-excel-fill-decision.md`。本書は、**最初の様式（在留期間更新）で確立した「セル座標の特定方法」と「テストの書き方」**を記録する。
後続の #84（変更）・#86（認定）・#88（取得）は、本書の手順をそのまま踏襲する。

## セル座標の特定方法（重要。後続の様式でも同じ手順）

### 1. 入力欄は「ロック解除されたセル」である

公式様式の各シートは**シート保護**がかかっており、利用者が入力するセルだけが、セルの保護設定「ロック」を外してある（`protection.locked === false`）。
そのため、入力欄の座標は、ラベルの位置関係から推測せず、**ロック解除セルを機械的に列挙して**特定する。

```js
import ExcelJS from "exceljs";
const wb = new ExcelJS.Workbook();
await wb.xlsx.readFile("docs/official/<様式>.xlsx");
const ws = wb.getWorksheet("<シート名>");
// 結合セルの左上以外（slave）は除く
ws.eachRow({ includeEmpty: true }, (row) =>
  row.eachCell({ includeEmpty: true }, (c) => {
    if (c.isMerged && c.master.address !== c.address) return;
    if (c.protection?.locked === false) console.log(c.address, c.isMerged ? ws.model.merges.find((m) => m.startsWith(c.address + ":")) : "", c.value ?? "");
  }));
```

### 2. ラベルとの対応は、行のラベル文字と照合する

ロック解除セルの行・列の近くにある日本語ラベル（項目番号・項目名）を、`docs/phase9-official-forms-research.md` と同梱の様式で照合して、`formMapping.ts` の項目に割り当てる。ラベルを読むには、結合セルの左上のセルだけを出力すると見やすい（結合セルは、すべてのセルに左上と同じ値が返るため）。

### 3. 書き込むのは、結合セルの「左上のセル」だけ

結合範囲の左上以外に値を書くと、表示されない。`renewal.test.ts` の「座標の整合テスト」が、全項目について、(a) ロック解除セルであること、(b) 結合セルの左上であること、(c) 同じセルを二重に指していないこと、を検査する。**対応表を作ったら、まずこのテストを通す**。

### 4. 桁ごとに分かれた欄・年月日が分かれた欄

* 法人番号（13桁）・雇用保険適用事業所番号（11桁。4-6-1桁）は、**1桁ごとのセル**。`digitItems` が、数字だけを取り出して1文字ずつ書く。
* 生年月日などは、年・月・日が別のセル（ラベル「年」「月」「日」の左隣の入力欄）。`dateItems` が分けて書く（先頭のゼロは除く）。
* 表（在日親族6行・職歴6件）は、行ごとにセルを展開する。あふれた分は書かず、`warnings` に出す。

### 5. 選択式（○を付ける）項目

様式の性別（男・女）・配偶者の有無（有・無）は、入力セルがなく、印刷された選択肢から選ぶ書式である。**ロック解除セルがない**ため、`PickItem`（選ばれた値に応じて、選択肢のセルの文字を書き換える）で扱う。性別は選ばれなかった側と「・」を空にし、配偶者は「有・無」を、選ばれた方だけにする。値が空なら何も変更しない。

### 6. シート名

実際のシート名は Issue 本文の呼称と異なり、末尾に空白（全角を含む）がある。`sheetKey()`（NFKC 正規化＋空白除去）で照合する。

| 本Issueでの呼称 | テンプレートの実際のシート名 |
|---|---|
| 申請人等作成用1 | `申請人用（更新）１` |
| 申請人等作成用2Ｎ | `申請人用２Ｎ `（末尾に半角空白） |
| 所属機関等作成用1Ｎ | `所属機関用１Ｎ `（末尾に半角空白） |
| 所属機関等作成用2Ｎ | `所属機関用２N　`（末尾に全角空白） |

`申請人用１（裏）`（提出不要の案内シート）、`業種一覧`、`職種一覧` は差し込み対象外。

## 設計判断

* **差し込み値は文字列で書く。** 日付の年・月・日、資本金、給与なども、数値にせず文字列のまま書く（桁区切り・単位などの書式を、テンプレート側に任せるため）。
* **業種・職種は、番号のときだけ書く。** 様式は「業種一覧／職種一覧」の番号を記入する欄だが、案件DBの業種は自由記述のため。番号でない場合は空欄にして、`warnings` で知らせる（番号への変換は後続）。
* **職歴の並び順**は、左の列を上から下へ、続いて右の列を上から下へ。
* **活動内容詳細**は2行（1行ずつの結合セル）。改行で区切り、3行目以降は2行目に続ける（`warnings` を出す）。
* `warnings`：申請人情報が未確定（`buildTranscription` と同じ文言）、親族・職歴のあふれ、番号でない業種・職種、桁数の合わない法人番号等。
* `auto`／`confirm`／`entered`／`always_confirm` の区分は、画面側（#80）が `formMapping.ts` から得る。本モジュールは値の差し込みのみを行う。

## exceljs で読み書きすると失われるもの（既知の制限）

出力ファイルとテンプレートを比較して確認した結果。**A4（`paperSize=9`）・倍率・向き・シート保護・結合セル・入力規則（□／■）・印刷範囲・列幅・書式は保たれる**。一方、次は保たれない。

* `申請人用（更新）１` の**写真枠（図形「写真 Photo 40mm×30mm」）**。exceljs は画像以外の図形（`drawing`）を書き出さない。
* `所属機関用２N` の手動改ページ（62行目）とヘッダー・フッター。
* プリンター設定の埋め込みデータ（`printerSettings*.bin`）。用紙サイズ・倍率は別に保持される。

写真枠は、行政書士が写真を貼る目印であり、様式の本質的な記載事項ではないが、必要であれば、後続で（例：出力後の zip に `drawing1.xml` を戻す後処理）対応する。

## 目視確認について

受け入れ基準の「Excel／LibreOffice で開いてレイアウトを目視確認」は、**本Issueの作業環境では LibreOffice が起動できず（テンプレートそのものも読み込めなかった）、実施できていない**。構造の比較（上記）と自動テストまでを確認済み。マージ前に、行政書士または担当者が、出力ファイルを Excel／LibreOffice で開いて確認すること。

## テストの書き方（後続の様式でも同じ）

1. **座標の整合テスト**：対応表の全項目が、テンプレートのロック解除セルの左上を指し、重複がないこと（機械的に検査できるため、座標の取り違えを防ぐ）。
2. **差し込み結果のテスト**：ダミー値（実案件の個人情報は使わない）を全項目に与えて `fill…Excel` を呼び、バッファを `exceljs` で読み直して、代表的なセルの値を確認する。年月日・桁ごとの欄・表の2行目以降も確認する。
3. **無入力テスト**：空の入力で、テンプレートの全セルの値が変わらないこと（リッチテキストは、書式を除いた文字列で比較）。
4. **レイアウト保持テスト**：用紙（A4）・倍率・向き・シート保護・結合セルが保たれること。
5. **warnings のテスト**：未確定・あふれ・形式不一致で、期待の文言が出ること。

セルの値の比較には、`renewal.test.ts` の `plain()`（リッチテキストを文字列にする）と `text(wb, シート名, セル)` を使う。テストは、各ケースで差し込みに1秒前後かかる（テンプレートが大きいため）。ケースを増やす場合は、1テスト5秒の上限に注意する。

## #80（画面・生成履歴への統合）への引き継ぎ

* `fillRenewalExcel` は Node.js ランタイム専用。API ルートには `export const runtime = "nodejs"` を指定する。
* Vercel 等では、`docs/official/*.xlsx` が、ファイル追跡の対象に入らない可能性がある。API ルートで使う際は、`next.config.ts` の `outputFileTracingIncludes` に `docs/official/**/*.xlsx` を指定し、本番相当の環境で読み込めることを確認する。
* ダウンロード画面には、出典（出入国在留管理庁）・加工している旨・「下書きであり、提出前に原本と照合する」旨を表示する（`docs/official/README.md` の利用条件）。
* `formMapping.ts`（転記補助シート）の廃止は #80 の範囲。本Issueでは変更していない。
