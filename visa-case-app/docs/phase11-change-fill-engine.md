# フェーズ11：在留資格変更許可申請書の差し込みエンジン（Issue #84）

方式は `docs/phase11-renewal-fill-engine.md`（#79）、画面・生成履歴への統合は `docs/phase11-official-form-ui.md`（#80）、項目番号は `docs/phase12-change-forms-research.md`（#83）。本書は、**変更様式で更新と異なる点**と設計判断を記録する。

> **追記（フェーズ15）**：本書の「チェックボックス・有無の○は対象外」という記述は、利用者の明示の指示により方針転換し、差し込み対応済み。詳細は `docs/phase15-checkbox-pick-fill-engine.md` を参照。

## Issue 本文と原本の食い違い（原本を正とした）

Issue 本文は「項目5以降が1つずつ繰り下がる」と書くが、原本のロック解除セルとラベルでは、次のとおり。

| 項目 | 更新 | 変更（原本） |
|---|---|---|
| 出生地 | なし | **5** |
| 配偶者の有無 | 5 | **6** |
| 職業 | 6 | **7** |
| 本国における居住地 | 7 | **8** |
| 住居地 | 8 | **9**（電話番号・携帯電話番号は項目9の欄内。独立した番号なし） |
| 旅券 以降 | 10〜 | 10〜（更新と同じ） |

`FORM_LAYOUTS.change`（#83）と同じ。`change.test.ts` が、画面の項目番号表と対応表の項番の一致を検査する。

## 更新様式との座標の違い（重要）

変更様式の4枚のうち、**項目は更新と同じでも、セルの位置が異なる**シートがある。更新の座標を流用せず、ロック解除セルの列挙から特定した。

| シート（実際の名称） | 更新との違い |
|---|---|
| `申請人用（変更）１` | 項目の並びが異なる（出生地・配偶者の位置、13に「希望する在留資格」と「在留期間」の2段、14変更の理由）。在日親族の表は68行目から（更新は64行目から） |
| `申請人用２Ｎ ` | 更新より行番号が1小さい。取次者の下段（所属機関等・電話番号）のみ2小さい（77行目） |
| `所属機関用１Ｎ ` | 更新より列が2つ左（例：名称 G24→E24、法人番号 T〜AF→R〜AD）。行は同じ |
| `所属機関用２N　 ` | 更新と同じ位置 |

`申請人用１（裏）`・`業種一覧`・`職種一覧` は差し込み対象外。シート名は末尾に全角を含む空白があるため、`sheetKey()`（NFKC＋空白除去）で照合する（#79 と同じ）。

## 設計判断

* **13 希望する在留資格**は、`CaseRecord.targetStatus`（案件情報の「変更後の在留資格」）を、そのまま書く。二重入力しないための #83 の方針。これを差し込みへ渡すため、`FillInput` と `OfficialFormContent["input"]` に任意の `targetStatus` を追加した（`officialFormInputOf`・`parseFillInput` も対応）。`FILLERS` の関数の引数に `targetStatus` を足したが、更新の関数は3引数のまま使える。
* **14 変更の理由**は `FormDetails.changeReason` を書く。`renewalReason` は書かない。**5 出生地**は `placeOfBirth`。
* **対象範囲**（`CHANGE_SPEC.isInScope`）は、Issue の要件どおり `procedureType === "change"` のみ。現在の在留資格は問わない（変更は、現在の在留資格が技術・人文知識・国際業務とは限らないため）。
* 様式は技術・人文知識・国際業務向け（申請人等作成用1・2N、所属機関等作成用1N・2N）。**変更後の在留資格が技術・人文知識・国際業務でない**場合と、**未入力**の場合は、`fillChangeExcel` が `warnings` に出す（生成は妨げない）。画面の事前表示（`officialFormScopeWarnings`）は現在の在留資格・手続種別のみを見るため、この警告は生成時にのみ出る。
* 法人番号・雇用保険適用事業所番号の桁数検査は、更新と同じ（`RENEWAL_DIGIT_CHECKS` を再利用）。警告の文言（申請人情報の未確定・あふれ・番号でない業種・職種）も更新と同じ。
* 更新の `renewalMapping.ts` は変更していない。小さな補助関数（日付分解・1桁ずつの欄など）は `changeMapping.ts` に同じものを置いた（並行する #86・#88 との競合を避けるため。共通化は別課題）。
* 既存テスト `tests/officialForm.test.ts` は、「変更は専用様式がない」ことを前提にしていた2か所を、専用様式がない手続種別（`other`）に変えた。変更の差し込みの確認を追加した。
* 過去に保存した公式様式の版（`content_json.officialForm.input`）には `targetStatus` がない。変更の版を再生成（ダウンロード時の再作成）しても、項目13は空欄になる。#80 の公式様式は更新のみだったため、実害は想定しない。

## 本Issueで差し込まない項目（空欄のまま）

#79 と同じ方針（チェックボックス・有無の○は対象外）。

| 項目 | 理由 |
|---|---|
| チェックボックス（□）の項目（契約の形態・就労予定期間・給与の年額／月額・最終学歴の区分・専攻分野・職歴の有無・情報処理資格の有無 等） | Issue の方針で対象外 |
| 15 犯罪処分の有無・16 在日親族の有無・同居の有無（有・無の○） | 同上。15の具体的内容と、16の親族の各欄は書く |
| 3(5)・9 の業種・職種（番号でない場合） | 案件DBは自由記述のため。`warnings` で知らせる |
| 4 就労予定期間、2 契約の形態 | チェックボックスと年月への分解が必要 |
| 所属機関等作成用1の上部の欄（X9〜AG10）、署名・作成年月日欄 | 現行の項目定義にない／自署 |

## exceljs で読み書きすると失われるもの（既知の制限）

#79 と同じ（`docs/phase11-renewal-fill-engine.md`）。A4（`paperSize=9`）・倍率・向き・シート保護・結合セル（テストで確認）・入力規則・印刷範囲・列幅・書式は保たれる。一方、次は保たれない（変更様式のテンプレートでも同じ）。

* 画像以外の図形（`drawing`。例：写真枠）、手動改ページ、ヘッダー・フッター、プリンター設定の埋め込みデータ。用紙サイズ・倍率は別に保持される。

## 目視確認について

受け入れ基準の「Excel／LibreOffice で開いてレイアウトを目視確認」は、**本Issueの作業環境では実施できていない**（#79 と同じ。構造の比較と自動テストまでを確認）。マージ前に、行政書士または担当者が、変更の案件で生成したファイルを Excel／LibreOffice で開き、氏名・在留カード番号・変更後の在留資格・変更の理由などが正しい欄に入っていることを確認すること。

## 後続（#86 認定・#88 取得）への引き継ぎ

* 座標は、更新のものから**機械的にずらさず**、必ずテンプレートのロック解除セルから特定する（変更様式で、更新から行・列がずれていた）。
* `targetStatus` は、`FillInput.targetStatus`・`Filler` の第4引数で渡せる（認定・取得の「希望する在留資格」にも使える）。
