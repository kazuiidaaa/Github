# フェーズ15：チェックボックス・有無の○（丸選択）の差し込み対応

`docs/phase11-renewal-fill-engine.md`（#79）・`phase11-change-fill-engine.md`（#84）・`phase11-coe-fill-engine.md`（#86）・`phase11-acquisition-fill-engine.md`（#88）は、いずれも「チェックボックス（□）」「有無の○（有・無、はい・いいえ）」の差し込みを、Issue の方針により対象外としていた（行政書士が様式上で手動選択する前提）。

本フェーズは、利用者（行政書士）からの明示の指示「チェックボックスや該当箇所に丸をつけるところも、反映がされてさないので直してください」を受け、**その方針を転換し、4様式すべてでチェックボックス・有無の○を実際に差し込む**。対象外のまま残すのは、案件DBに対応する入力がない項目、および原本のプルダウンが号・種別まで区別できない一部のCOE選択肢のみとする。

以下の各節で「対象外」としていた記述は、本フェーズにより更新されている。本書は、その更新内容をまとめて記録する。

## 対象にした項目

既存の `PickItem`（「選ばれた側だけを残す」仕組み。`renewalMapping.ts`）を、そのまま拡張して使った。新しいパターンを作らず、既存の4パターン（単一セル書き換え・3分割セル・詳細欄つき5分割セル・注記文埋め込み）に、チェックボックス一覧（□→■）のパターンを1つ追加しただけである。

| 様式 | 新たに差し込む項目 |
|---|---|
| 更新 | 15 犯罪を理由とする処分の有無、16 在日親族及び同居者の有無、在日親族各行の同居の有無（6行） |
| 変更 | 15 犯罪を理由とする処分の有無、16 在日親族及び同居者の有無、在日親族各行の同居の有無（6行） |
| 認定 | 11 入国目的（チェックボックス34個）、15 同伴者の有無、17 過去の出入国歴の有無、18 過去の認定証明書交付申請歴の有無、19 犯罪を理由とする処分の有無、20 退去強制又は出国命令による出国の有無、21 在日親族及び同居者の有無、在日親族各行の同居予定の有無（4行） |
| 取得 | 11 在留資格取得の事由（チェックボックス3個）、13 希望する在留資格（チェックボックス4個＋その他）、14 犯罪を理由とする処分の有無、在日親族各行の同居（4行。「はい・いいえ」表記） |

いずれも、値が未入力（空文字）の場合は、テンプレートの元の状態（`有・無`・`はい・いいえ`・`□` のまま）を変更しない。`PickItem.writes` に対応するキーがなければ何もしない、という既存の仕組みをそのまま使っているため、空欄のセルを誤って消す・書き換える心配はない。

## チェックボックスの表現：「■」（U+25A0 BLACK SQUARE）

原本の印刷済み文字は「□」（U+25A1 WHITE SQUARE）。選択を示すため、該当のセルの文字を「■」（黒四角）に置き換える方式にした。

* 原本のフォント（ＭＳ Ｐ明朝）は「■」を問題なく表示できることを確認済み。
* 対象のチェックボックスセル（COE項目11、取得の項目11・13）は、`openpyxl` で確認した結果、原本側で `protection.locked == False`（ロック解除）になっている。つまり、様式の設計自体が「ここは人が直接書き込む欄」として想定しているセルであり、■への置き換えは様式の意図に沿っている（既存の性別・配偶者等、ラベル文字を書き換える方式のセルはロックされたままで、挙動が異なる。各様式の `*.test.ts` で、ロック状態をチェックボックス欄とそれ以外に分けて確認している）。
* 選ばれなかった他のチェックボックスは、**そのまま「□」として残す**（空文字にしない）。複数の□のうち1つだけを■にする、という原本の見た目に最も近い表現のため。

## 認定（COE）項目11「入国目的」：34択のうち、曖昧さのない場合だけチェックする

認定の項目11は、34個のチェックボックスから1つを選ぶ方式（`coeMapping.ts` の `COE_PURPOSE_CHECKBOXES`）。案件の「希望する在留資格」（`targetStatus`。`lib/types.ts` の `RESIDENCE_STATUSES` という固定のプルダウン値）と、様式の選択肢の文字列が**一字一句完全に一致する場合だけ**、該当の□を■にする。

一致しない場合（プルダウンにない表記、または下記の号・種別まで様式側で区別が必要な場合）は、チェックを付けずに `warnings` で案内する。これは、不正確な選択を公的書類に書き込むリスクを避けるための判断である。

* 高度専門職の号（1号イ／ロ／ハ）は、案件の「希望する在留資格」（変更は「変更後」）で2段階に選べる（Issue #181）。保存値は様式の選択肢と同じ文字列（例：「高度専門職（1号ロ）」）で、DB の変更はない。一致した号の□だけが■になり、号が未選択の「高度専門職」は、チェックなしで「号を選択してください」と警告する。「特定技能」「技能実習」「特定活動」は、案件側で号・種別まで持たないため、従来どおり一致せず警告が出る（別途検討）。様式 N 以外（I・L・M・U）の雛形取り込みと、「行う活動」による様式の選択は、未対応（#181 の残り・#187）。
* 「その他」の□も、案件側に対応する入力欄（自由記述）がないため、対象外のまま。

## テストでの確認観点

各様式の `*.test.ts` に、次の観点を追加した（`acquisition.test.ts` が先行実装、`renewal.test.ts`・`change.test.ts`・`coe.test.ts` も同じ方針）。

* 新しい `PickItem` の `no` 一覧が、実装した項目数と一致すること（既存の座標整合テストの延長）。
* 「有」「無」それぞれを選んだ場合に、選ばれた側の文字が残り、もう一方と「・」が消えること。
* 入力がない（相手がいない・該当者がいない）行は、原本の元の表記（`有・無`・`はい・いいえ`）がそのまま残ること（空文字にならない）。
* チェックボックス形式は、選ばれた□だけが「■」になり、他の□は「□」のまま残ること。
* 認定の入国目的は、一致する場合に■が付き、一致しない（号・種別が必要）場合はどの□にも触れず、`warnings` に案内が出ること。

## 目視確認

LibreOffice（`soffice --headless --convert-to pdf`）でダミーデータを差し込んだ4様式を変換し、PDFを画像化して確認した。性別・配偶者の有無（既存）、犯罪歴・在日親族の有無とその注記文、在日親族各行の同居（有・無／はい・いいえ）、COE項目11の■とその他の□、取得の事由・希望する在留資格の■と□が、いずれも意図どおり表示されることを確認した。
