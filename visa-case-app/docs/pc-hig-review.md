# PC 版 HIG 適合レビュー（Issue #456）

PC 版（Mac 風。#481〜#486 で作り替え済み）を、Apple の Human Interface Guidelines（macOS）に照らして見直した記録。iPhone 版の「画面構成と HIG 適合レビューの反映」（`docs/mobile-ios.md`）と同じ進め方。

## 進め方
- 実画面を Playwright（chromium、幅 800・1280、明色・暗色、文字 200%）で開き、スクリーンショットを見て判断した。データは、架空の案件（`lib/demoSeed.ts` の 3 件を複製）を、ブラウザ内の仮データ方式（Supabase 未接続）で入れた。本番の Supabase には触れていない。
- 見た観点：サイドバー、ツールバー、一覧・表、インスペクタ、フォーム、ダイアログ、ボタンの階層、焦点の輪、キーボード操作、文字の大きさ・行間、余白、色の対比、暗色、文字拡大、日本語の文言。
- 値はトークン（`tokens/mac.tokens.json`）から引き、直書きはしていない（新しいトークンは追加していない）。

## 問題なしと確認したもの
- サイドバー：選択行は背景・太字・左の線で示す。固定（sticky）で、暗色でも対比は十分。文字 200% でも折り返して読める。
- ツールバー：折り返しと、狭い幅での短い表記が働く。ダイアログは、ツールバーの上に出る。
- 案件一覧の表：見出しの並べ替え（aria-sort と ▲▼）、矢印キーでの行移動、選択行の印、幅が足りないときのカード切替。
- ダイアログ：キャンセルが先、実行が右端。見出し 17px、角丸 12px、暗色でも読める。
- 暗色：新しく見つかった対比の問題は無い。
- 焦点の輪：全域で、青（#007aff / #0a84ff）、オフセット 2px。

## 44px の影響範囲（#392 の判断材料。今回は変更しない）
本文中の操作の高さは、`min-h-[44px]` を各部品・各画面に書いて保っている。
- 書き込み箇所：`app/`・`components/` の 49 ファイル、97 か所。共通部品（`components/ui.tsx` の `Button`・`inputClass`、`ChoiceGroup`、`Modal` の操作）に集まっている。
- 28px（`control-height-mac-regular`）へ変える場合：共通部品だけでは足りず、画面ごとの書き込みも直す必要がある。PC 版のみ（幅 md 以上、`/m` 以外）に限るなら、`mac-button`・`mac-input` の読み替え（`app/globals.css`）に高さを足す方法が、変更が小さい。
- 画面への影響：一覧の表の見出し・行、フォームの縦の長さ、「必要書類」の表の行の高さが縮み、1 画面に出る情報が増える。一方、マウスでの押しやすさ（#392 の目的）は下がる。タッチ操作の PC では、押し間違いが増えるおそれがある。
- 変わらないもの：WCAG 2.5.8 の最小（24px）は満たせる。文字の大きさ・対比は変わらない。
- 決めること：PC 版のみ 28〜32px にするか、44px を保つか。範囲（ボタンのみ／入力欄・表も）。利用者の判断とする。
