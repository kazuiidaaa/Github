# ご案内書類の言語（日本語・英語・韓国語）

Issue #251。依頼者向けの「ご案内書類」（`client_guide`）を、日本語・英語・韓国語のいずれかで、画面表示・Word・PDF に出せる。

## 方針（決定事項）
1. 翻訳 API は使わない。訳文は、アプリ内の訳表（コード上の定数）として持つ。外部へ、個人情報を送らない。
2. 言語は、案件ごとの設定ではなく、案内書を表示・出力する際に、行政書士・スタッフが選ぶ。選んだ言語は、案件にも、保存済みの案内書（content_json）にも書き込まない。過去の版は、日本語のまま変わらない。
3. 直前に選んだ言語は、ブラウザ（localStorage、キー `visa-case-app:client-guide-lang`）に記憶し、次回の既定にする。使えない場合も、画面は壊れない。
4. 自由記述（備考など）、宛名、連絡先、氏名は、翻訳せず、原文のまま載せる。行政書士が追加した書類名も、自由記述として、原文のまま載せる。
5. 対象言語は、日本語（既定）・英語・韓国語。
6. 書類名は、訳文のあとに、日本語の原文を括弧で併記する（役所の窓口などで、日本語の名称を伝えられるようにするため）。
   - 訳がある：`Residence certificate（住民票）`、`주민표（住民票）`
   - 訳がない：`原文（Not translated）`、`原文（번역 미확인）`
   - 日本語を選んだ場合は、併記しない。
   - 書式は、`requirementNameCell`（`lib/documents/clientGuide.ts`）の1か所で決める。画面・Word・PDF で、同じ結果になる。
7. 訳文の確認は、依頼者へお渡しする前に、行政書士が行う。

## 訳表の置き場所
| 内容 | ファイル |
| --- | --- |
| 言語の型（`Lang`）、記憶（localStorage） | `lib/documents/lang.ts` |
| 固定の文（見出し、案内文、受領の状況、文書の状態、提出時の注意の定型文）、取得先の目安、注意書き、手続の名称 | `lib/documents/clientGuideText.ts` |
| 規則（`lib/requirements/rules.ts`）の書類名 | `lib/documents/clientGuideNames.ts` |

保存済みの content_json は、日本語の原文を持つ。言語の切替は、表示・出力の時点で、訳表を引いて行う（`buildBlocks(doc, lang)`）。提出時の注意（写し・原本・発行日・撮影日）は、保存済みの日本語の定型文を、月数はそのままに、言語ごとの文へ直す。

## 訳文の確認の手順（行政書士）
1. 画面で、英語・韓国語に切り替え、訳文を読む。
2. 誤り・不自然な点は、上の表のファイルの訳文を直す（`clientGuideText.ts` は言語ごとの項目、`clientGuideNames.ts` は書類名ごとに英語・韓国語の順）。
3. 依頼者へお渡しする前に、行政書士が、訳文を確認する。確認前の訳文は、AI が作成した下書きである。
4. 規則（`rules.ts`）の書類名を変更した場合は、`clientGuideNames.ts` のキーも同じ文字列に直す。直さないと、訳が外れ、「Not translated」の目印が付く（試験が、取り残しを検出する）。

## 訳がない書類名の扱い
- 規則の書類名で、訳表にないものは、日本語の原文のあとに「（Not translated）」「（번역 미확인）」を付け、表の下に説明の注記を出す。
- 現在、訳がないのは、高度専門職のポイント計算表の疎明資料（`疎明資料 ①（学歴）：…` など、21件）のみ。ポイント計算表の項目から動的に作る名称のため。
- 一覧は、`tests/clientGuideLang.test.ts` の実行時に出力される（`訳がない書類名：…`）。

## 出力の言語と版の記録
- Word・PDF は、画面で選んだ言語の内容で出力する。出力した版（docx・pdf）の記録には、言語を残さない。
- Supabase 利用時は、出力時のファイルが保管庫に残る。再度のダウンロードでは、出力時の言語のファイルが得られる。
- 仮データ（ブラウザ内保存）の利用時は、ダウンロードのたびに、保存内容から作り直す。出力した版の画面からの再ダウンロードは、日本語になる。
- 言語を選べるのは、画面の版（`html`）のみ。

## Word
- 日本語・英語は、従来どおり Yu Gothic。
- 韓国語は、Yu Gothic にハングルがないため、Malgun Gothic（Windows 標準）を指定し、文書の言語を `ko-KR` とする。ない環境では、Word が代わりの書体を選ぶ。
- Word 本体での表示は、未確認（XML の指定と、LibreOffice での変換のみ確認）。

## PDF とフォント
- PDF は、ブラウザ上で `pdf-lib` により作る。日本語・英語は日本語フォント、韓国語は韓国語フォントを先に使い、足りない文字（漢字・かな）は日本語フォントで補う（`FontSet`）。
- フォントは、Noto Sans JP・Noto Sans KR（どちらも太さ 400 の Regular、SIL Open Font License 1.1）。リポジトリには同梱せず、外部（jsDelivr。npm の `@expo-google-fonts/noto-sans-jp`・`noto-sans-kr`、版 0.4.4 を固定）から取得する（`lib/documents/pdf.ts` の `JAPANESE_FONT_URL`、`KOREAN_FONT_URL`）。出典・ライセンスは、Google Fonts の OFL。
- 日本語のフォントを先に使い、ハングルだけ韓国語のフォントで描く（`FontSet`、`lib/documents/store.ts`）。Noto Sans JP にハングルは無く、Noto Sans KR のかな・漢字は韓国語の字形になるため、1本にはできない。
- 韓国語のフォントは、韓国語版、または、氏名などにハングルを含む書類のときだけ取得する（約 6.2MB）。含まない日本語版・英語版は、日本語のフォント（約 5.7MB）のみ。
- `pdf-lib` の文字の絞り込み（`subset: true`）は、字形データを途中で切り、文字が欠けるため使わない。フォント全体を埋め込む。PDF の容量は、日本語のフォントのみで約 3.4MB、韓国語のフォントも含むと約 6.5MB。
- `locl`（地域別の字形の置換）と `liga`（合字。英文の ffi・fi など）は切る。置換後の字形の幅が登録されず、英数字だけの文で数字の間隔が広がり、英文で合字の後ろが空くため。

### 経緯：OTF（CFF）フォントでの文字化け（#253、解消済み）
- #249 で、フォントが TrueType から OTF（CFF 輪郭）に変わった。`pdf-lib` は、CFF 輪郭の OpenType を正しく埋め込めない。日本語・韓国語の PDF で、文字が化ける、文字幅が登録されず表のセルで文字がはみ出す・重なる・本文が右端で切れる、という症状が出た。
- 対応として、固定の太さ（400）の TrueType に差し替えた。Google Fonts の可変フォント（`[wght]`）は、可変軸の既定値が Thin（100）で、`pdf-lib` は軸を指定して埋め込めないため、PDF で細く描かれる。このため使わない。同じ書体の、太さ 400 で固定した TrueType を、npm の `@expo-google-fonts` から取得する。
- 検討した他の案: BIZ UDPゴシック（日本語）・ナヌムゴシック（韓国語）の2本立て（サイズは小さいが、書体が Noto Sans と異なる）。
