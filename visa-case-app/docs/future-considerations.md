# 今後あらためて検討する設計課題

作成日：2026-10-03 / 状態：**保留**（今回はIssue化を見送り、設計をあらためて検討する）

## 1. 所属機関（雇用先）情報の、複数案件にまたがる共有化

背景：Issue「同一所属機関の複数の申請人をまとめて新規登録できるようにする」の検討にあたり、同一の会社に所属する複数の申請人の案件であっても、雇用・会社情報（`employment_details` テーブル、`components/EmploymentForm.tsx`）が案件ごとに独立して保持されている構成であることを確認した。

今回の対応：新規案件の作成時に、入力した雇用・会社情報を複製して、複数案件をまとめて作成する簡易な対応にとどめる。作成後の案件間で情報を同期する仕組みは導入しない（各案件は、作成直後から独立したレコードとして扱う）。

今後の検討課題：所属機関を、案件から独立した共有エンティティとして管理し、1か所の変更を関連する全案件に反映できるようにするかどうか。実現する場合は、次の点の検討が必要になる。

- データモデル：`organizations`（本アプリを利用する事務所を表す既存テーブル）とは別に、「顧客の所属機関」を表すテーブルを新設するか、`employment_details` の持ち方自体を見直すか
- 既存データの移行方法（案件ごとに保持している雇用・会社情報を、共有エンティティへどう統合するか）
- 1つの所属機関情報を、複数の案件・複数の行政書士が参照する際の、権限・編集競合の扱い
- 必要書類の判定（`lib/requirements/evaluate.ts`）など、雇用・会社情報を参照している既存ロジックへの影響範囲

要確認：上記の設計変更に見合う利用規模（同一所属機関の案件数）になった時点で、あらためて検討する。
