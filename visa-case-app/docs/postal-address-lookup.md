# 郵便番号から住所の前半を入れる機能（Issue #226）

## 目的
住所の入力欄の近くに郵便番号（7桁）を入れると、都道府県・市区町村・町域を、住所の欄へ入れる。番地以降は、利用者が続けて入力する。

## 方式
- 外部サービス「日本郵便 郵便番号・デジタルアドレスAPI」（v2）を使う（利用者の決定。同梱データ方式は採らない）。
- 呼び出しは、ブラウザーから直接ではなく、サーバー側の `app/api/postal-code/route.ts` から行う。認証情報を画面へ出さない。
- ブラウザーが接続するのは、このアプリ自身の `/api/postal-code` のみ。外部への通信は、サーバーから行うため、`next.config.ts` の通信の制限（CSP）は変更していない。
- 流れ（`lib/japanPost.ts`）
  1. トークン取得：`POST {BASE}/api/v2/j/token`（`grant_type=client_credentials`）。取得したトークンは、期限（`expires_in`）の1分前まで再利用する。検索が 401 のときは、1回だけ取り直す。
  2. 住所検索：`GET {BASE}/api/v2/searchcode/{7桁}?choikitype=1&searchtype=2`（町域に括弧なし、事業所個別郵便番号を除く）。
  3. 応答の `addresses` から、都道府県・市区町村・町域をつなぐ。候補が複数あり食い違う場合は、一致する項目までを入れる。
- 住所は、API が返した全角のまま入れる（`normalize` を通すが、全角はそのまま）。入れた後も、利用者が編集できる。
- 入力済みの住所は、確認なしに上書きしない。「置き換える」の確認を挟む（`components/ConfirmDialog.tsx`）。

## 送信する情報
- 日本郵便へ送るのは、**郵便番号（7桁の数字）のみ**。氏名・住所・案件の情報は送らない。
- 認証のために、クライアントID・シークレットキー（環境変数）と、必須ヘッダーの接続元 IP（`x-forwarded-for`）・`User-Agent` を送る。
- 郵便番号は、住所とは別に保存しない。保存するのは、住所の欄の文字のみ（郵便番号の入力欄は、画面の中だけで扱う）。
- ログに、郵便番号・認証情報を残さない。

## 環境変数（サーバー側のみ。Vercel に登録）
| 名前 | 内容 |
|---|---|
| `JAPANPOST_API_BASE_URL` | API のベース URL（https のみ） |
| `JAPANPOST_CLIENT_ID` | クライアント ID |
| `JAPANPOST_SECRET_KEY` | シークレットキー |

- 1つでも未設定、または URL が https でないときは、自動入力は動かず、住所は手入力のまま使える（案件の入力は止めない）。画面には「自動入力は、設定されていません」と表示する。
- 値は、コード・テスト・ログ・Issue・PR に書かない。試験は、外部通信を模擬して行う。

## 失敗したとき
- 通信の失敗・認証の失敗・サーバーの異常：「住所を取得できませんでした。住所は手入力してください。」
- 該当なし：「該当が見つかりませんでした。住所は手入力してください。」
- どちらも、住所は手入力のまま使える。

## 画面への組み込み
- 部品：`components/AddressField.tsx`（郵便番号と住所を組にした入力部品）。`id`（住所の入力欄）、`normalize`（住所を保存前に通す変換。既定は、半角を全角にする変換（#223、`docs/zenkaku-input.md`）。補った住所にも、手入力の住所の確定時にも適用）、`lookup`（検索の差し替え。試験用）を受け取る。
- 適用した住所の欄：申請人情報の「住居地」、雇用・会社情報の「所在地」、様式の追加項目の代理人・保証人・取次者・派遣元の住所。
- 適用しない欄：様式の追加項目の「本国における居住地」（日本の住所ではない）。

## API の呼び出しの制限（`app/api/postal-code/route.ts`）
- ログインが必要（Supabase 設定済みの環境）。1分に30回まで（ユーザー単位）。本文は1,000バイトまで。

## 利用者の確認事項
- `x-forwarded-for`：このアプリは、利用者の端末からの接続元 IP（Vercel が付与する `x-forwarded-for` の先頭）を、そのまま日本郵便へ渡している。この扱いでよいか。
- `User-Agent`：固定の文字列 `visa-case-app` を送っている。指定があれば変更する。
- 接続元 IP の制限の有無（Vercel のサーバーの出口 IP は固定でない）。
- `ec_uid`（提供者のユーザー ID）が必要か。現在は送っていない。
- 本番の認証情報・URL への切り替えの時期。
- 検索の `Authorization` ヘッダーの形式（`Bearer {token}`）と、応答の項目名（`addresses[].pref_name` / `city_name` / `town_name`）は、公開資料に基づく想定。試験用 API で確認する。
