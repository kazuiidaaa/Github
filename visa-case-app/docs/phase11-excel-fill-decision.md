# フェーズ11 方針決定：公式様式（エクセル）への直接差し込み方式への転換

作成日：2026-10-03 / 状態：**決定済み**（行政書士の判断）

## 背景

フェーズ9（`docs/phase9-official-forms-research.md`）では、在留期間更新許可申請書（技術・人文知識・国際業務）について、公式様式への直接差し込み（当時の「案B」）ではなく、独自レイアウトの確認用書類「転記補助シート」（当時の「案A」）を採用した。理由は、公式PDFが入力欄を持たない図形ベースである可能性、様式改正による位置ずれ、利用条件の未確認、であった（同書10章）。

今回、行政書士より、在留期間更新・在留資格変更・在留資格認定証明書交付・在留資格取得の4様式について、**案件情報を公式エクセル様式の対応欄に直接差し込み、差し込み済みのエクセルファイルを申請書類として出力する**方式への転換が指示された。これは、フェーズ9の「案A」から「案B」への転換にあたる。

## 決定事項

| 事項 | 決定 |
|---|---|
| 差し込み方式 | 公式エクセル様式（`.xlsx`）のセルへ、案件情報を直接書き込む。PDFへの差し込み（画像ベースのPDFへの上書き）は採用しない。エクセルはセル単位での値の指定ができ、様式改正時の位置特定も、PDFより確実に行えるため |
| 対応順序 | 在留期間更新許可申請（既存データ項目が最も揃っている）を先行して実装し、基盤（差し込みエンジンの実装方式）を確立したうえで、在留資格変更許可申請・在留資格認定証明書交付申請・在留資格取得許可申請の順に展開する |
| 公式エクセル様式ファイルの保持 | 事務所ごとのアップロード方式ではなく、**リポジトリに同梱**する（全事務所共通のテンプレートとして使う）。`docs/official/` に配置し、出典（出入国在留管理庁ホームページ）および、本アプリによる加工（セルへの入力）を行っている旨を明記する |
| 転記補助シート（`lib/documents/formMapping.ts` による独自レイアウトの確認用書類） | **廃止し、差し込み方式のエクセル出力に置き換える** |
| PDF化（A4印刷） | 本アプリでは当面行わない。差し込み済みのエクセルファイルをダウンロードし、行政書士が自身のExcel・LibreOffice等から「印刷」→「PDFとして保存」する運用とする。理由：差し込み済みエクセルをサーバー側でA4レイアウトのPDFに変換するには、LibreOffice等の変換エンジンが必要だが、Vercelの標準的なサーバーレス実行環境では利用できない。外部の変換API・自前の変換サーバーの導入は、旅券番号・犯罪歴・家族情報等の機微な案件データの外部送信、または新たなホスティング・運用負担を伴うため、今回は見送る |
| 必要書類判定ルール（`lib/requirements/rules.ts`） | 在留資格変更・認定・取得についても、フェーズ9と同様の調査（入管庁の公式案内・提出書類チェックシートの確認）を行い、整備する（当初の依頼範囲外だったが、追加候補として対応する） |

## 今後の実装で踏襲すること

- 差し込みの元データとなる案件情報の算出ロジックは、`lib/documents/formMapping.ts`（`buildTranscription` とその項目定義）の考え方を踏襲してよい（公式項目番号ごとに、案件DBのどの値を使うか、確定済みか行政書士の確認が必要かを区別する設計）。ただし出力先がテキストレイアウトではなく、テンプレートのセルになる点が異なるため、項目定義とセル座標の対応表は、様式ごとに新規のモジュールとして作成する。
- 生成・保存・版管理・確認状態（下書き・確認済み・最終版・保管）の既存の仕組み（`lib/documents/store.ts`、`supabase/migrations/0008・0010・0011・0015`）は、ファイル種別に「差し込み済みエクセル」を追加する形で再利用する。
- 出力したファイルは下書きであり、提出前に行政書士が原本と照合する旨の注意書きを、ダウンロード画面に表示する（公式様式そのものに透かし等は入れない。提出書類としてそのまま使えることを優先する）。
- 公式様式の利用条件（PDL1.0）に基づき、出典表示および加工している旨の表示を、ダウンロード画面および `docs/official/README.md` に明記する。
