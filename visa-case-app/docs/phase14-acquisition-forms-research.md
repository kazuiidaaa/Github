# フェーズ14 調査報告書:在留資格取得許可申請の様式対応

対象手続:在留資格取得許可申請(別記第三十六号様式(第二十四条関係))
根拠資料:`docs/official/acquisition-application-form_930004121.xlsx`(単一シート「取得 (反映)」)。Issue #87。
状態:様式の項目番号・項目名は、上記Excelのセル内容から確認した。法令上の要否・添付書類の規則は、本書の対象外(必要書類の判定規則は未整備)。

## 0. 調査の前提

- 本書は、`docs/phase9-official-forms-research.md`(更新様式)と同じ構成で、取得様式の入力項目と案件DBとの対応をまとめる。
- 取得許可申請は、出生または日本国籍の離脱・喪失等により、上陸の手続を経ずに在留資格を取得する場合の手続である。就労系の在留資格(技術・人文知識・国際業務等)を前提とする所属機関用の用紙はない(用紙は1枚)。
- 実案件の個人情報は、コード・テスト・本書に含めない。

## 1. 使用する公式様式

- 様式名:別記第三十六号様式(第二十四条関係)「在留資格取得許可申請書」。
- 用紙:1枚(申請人等作成用のみ。所属機関用の用紙はない)。更新様式のような「申請人等作成用2(N)」「所属機関等作成用」は存在しない。
- 添付の写真欄はない(様式上の記載は確認できなかった)。

## 2. 公式様式の入力項目(公式の表記)

1 国籍・地域 / 2 生年月日 / 3 氏名 / 4 性別 / 5 出生地 / 6 配偶者の有無 / 7 職業 / 8 本国における居住地 / 9 住居地(電話番号、携帯電話番号) / 10 旅券((1)番号、(2)有効期限) / 11 在留資格取得の事由(出生・国籍離脱・喪失・その他) / 12 在留の理由 / 13 希望する在留資格(永住者の配偶者等・日本人の配偶者等・定住者・家族滞在・その他)と在留期間 / 14 犯罪を理由とする処分を受けたことの有無(日本国外を含む) / 15 在日親族及び同居者(続柄、氏名、生年月日、国籍・地域、同居、勤務先・通学先、在留カード番号または特別永住者証明書番号) / 16 在日身元保証人又は連絡先((1)氏名、(2)本人との関係、(3)住所、電話番号、携帯電話番号) / 17 代理人(法定代理人による申請の場合。(1)氏名、(2)本人との関係、(3)住所、電話番号、携帯電話番号) / 署名・申請書作成年月日 / 取次者((1)氏名、(2)住所、(3)所属機関等、電話番号)

## 3. 案件DBとの対応

| 様式の項目 | 対応先 | 区分 |
|---|---|---|
| 1 国籍・地域 / 2 生年月日 / 3 氏名 / 4 性別 | `Applicant` の既存項目 | 既存(自動) |
| 5 出生地 | `FormDetails.placeOfBirth` | 追加(#83と共通の項目名) |
| 6 配偶者の有無 | `FormDetails.maritalStatus` | 既存を流用 |
| 7 職業 | `FormDetails.occupation` | 既存を流用 |
| 8 本国における居住地 | `FormDetails.homeAddress` | 既存を流用 |
| 9 住居地 / 電話番号・携帯電話番号 | `Applicant` の住居地 / `FormDetails.phone`・`mobilePhone` | 既存を流用 |
| 10 旅券 | `FormDetails.passportNumber`・`passportExpiry` | 既存を流用 |
| 11 在留資格取得の事由 | `FormDetails.acquisitionCause`(`birth`/`nationalityLoss`/`other`)・`acquisitionCauseOther` | 追加 |
| 12 在留の理由 | `FormDetails.stayPurpose` | 追加 |
| 13 希望する在留資格 | `CaseRecord.targetStatus`(案件情報) | 既存(二重入力しない) |
| 13 在留期間 | `FormDetails.desiredPeriod` | 既存を流用 |
| 14 犯罪を理由とする処分 | `FormDetails.criminalRecord`・`criminalDetail` | 既存を流用 |
| 15 在日親族及び同居者 | `FormDetails.relativesPresent`・`relatives` | 既存を流用 |
| 16 在日身元保証人又は連絡先 | `FormDetails.guarantorName`・`guarantorRelationship`・`guarantorAddress`・`guarantorPhone`・`guarantorMobilePhone` | 追加 |
| 17 代理人 | `FormDetails.legalRepName`・`legalRepRelationship`・`legalRepAddress`・`legalRepPhone` | 既存を流用(項目の意味が同じ) |
| 取次者 | `FormDetails.agentName` 等 | 既存を流用 |

代理人(17)は、更新様式の「22 代理人」と同じ意味(法定代理人による申請の場合)なので、既存項目を流用し、新規項目を増やさない。携帯電話番号(17の欄にある)は、既存に項目がなく、更新様式の22にもないため、追加しない(必要になれば別Issueで対応)。

## 4. 自動差し込みの可否と手動確認

- 自動で載る見込みの項目:1〜4、9(住居地)(`Applicant`から)。
- 手動入力・確認が必要な項目:5〜8、9(電話)、10〜17、取次者。
- 本Issueの範囲では、転記補助シート・Excel差し込みは、取得様式に対応していない(現在は更新様式のみ)。取得案件で転記補助シートを生成すると、「対象外の可能性があります」の警告が表示される(既存の挙動)。

## 5. 設計判断

- 手続種別 `acquisition`(ラベル「在留資格取得許可申請」)を `PROCEDURE_TYPES` に追加した。`needsTarget`(新規案件作成・案件情報編集)に含め、「希望する在留資格」を必須の入力とした。
- 希望する在留資格の選択肢は、既存の全在留資格のままとした(Issueが許容)。様式の4種+その他に限定すると、`RESIDENCE_STATUSES`・`STATUS_HINTS`・規則との整合の確認が必要になるため、見送った。
- 「公式様式項目」タブは、`procedureType === "acquisition"` のとき、更新様式向けのセクション(申請人等作成用1・2、職歴、所属機関等)を表示せず、取得様式の項目番号どおりのセクションを表示する。更新様式の表示・動作は変えない。項目番号つきのラベルは、`lib/formDetails.ts` の `ACQUISITION_LABELS` に持つ。
- 「雇用・会社」タブは、取得案件でも従来どおり開けるが、入力は必須ではない。必要書類の判定は、取得の規則が未整備のため「対象外」の案内を表示し、「雇用・会社」の入力を求めない(`lib/requirements/evaluate.ts`、変更なし)。他タブ・書類作成は、`EmploymentInfo` が空でも動作する。
- データベースの手続種別の制約(`cases.procedure_type` の check)に `acquisition` を加える移行 `supabase/migrations/0016_procedure_type_acquisition.sql` を追加した。本番では、アプリの更新前または同時に実行する(未実行だと、取得案件の保存が失敗する)。

## 6. #83(変更許可申請)・#85(認定)との衝突が想定される箇所

#83 は、`FormDetailsForm.tsx` に手続種別ごとの項目番号表を導入する。本Issueは、これに依存せず、追加中心で実装した。マージ時は次を調整する。

- `lib/formDetails.ts`:`FormDetails`・`EMPTY_FORM_DETAILS` の末尾に追加した(`placeOfBirth` は #83 と同名。重複した場合は一方を残す)。`ACQUISITION_LABELS` は、#83 の項目番号表に統合できる(キーは `FormDetails` のキー)。
- `components/FormDetailsForm.tsx`:`isAcquisition` による分岐(取得用の2つのセクション、更新用セクションの条件表示)と、親族の見出し1行。#83 が項目番号をハードコードから表引きに書き換えた場合、取得用セクションのラベルを、その表へ移すのが望ましい。
- `lib/types.ts`:`PROCEDURE_TYPES` に1要素を追加(#85 が `coe` を変更する場合、近接した行で競合しうる)。
- `app/cases/new/page.tsx`・`components/CaseInfoEditor.tsx`:`needsTarget` の1行(#85 と同じ行を変更しうる)。
- 移行ファイル番号:0016 を使用した。他のIssueが同番号を使う場合は、番号を振り直す。
