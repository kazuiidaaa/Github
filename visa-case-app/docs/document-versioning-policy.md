# 生成文書の版管理の方針（協議の記録）

高度専門職のポイント計算表（Issue #186）を生成履歴へ載せる検討の中で、版管理そのものの方針を協議した。現状（実装済み）と、決まった方針（未実装）を分けて記録する。

## 現状（実装済み）
- 生成のたびに、新しい版（v1, v2…）を追記する。版の削除はできない（`generated_documents` に削除のポリシーがない）。
- Word・PDF・Excel は、出力のたびに別の版（行）と、保管庫（Supabase Storage の `generated-documents`）のファイルが増える。
- 状態は、確認前（draft）→ 行政書士確認済み（reviewed）→ 最終版（final）→ 保管（archived）。
- ファイルの削除は、owner・admin のみ（案件の削除用）。

## 決まった方針（未実装）
1. **上限**：申請人ごと・文書の種類ごとに、確認前の版は**最新の1つ**のみ。
2. **確認前の版は「更新」する**：新しい版を足して古い版を消すのではなく、同じ行を更新する（版番号を進め、内容を差し替える）。保管庫のファイルも、同じ保存先へ上書きする。削除の操作・権限は、不要になる。更新は、監査ログに残す。
3. **確認済み・提出済みの版は、上書きも削除もしない。**
4. **「最終版」を廃止し、「提出済み」（`submitted`）にする**：確認前 → 行政書士確認済み → 提出済み → 保管。既存の `final` は、`submitted` に読み替える（DB の制約と遷移の規則の変更が必要）。
5. **確認済み以降の変更は、修正依頼で行う**：
   - 変更したい人が、理由つきで依頼を出す。
   - 承認できるのは、**確認した行政書士本人**または **owner・admin**。
   - 承認すると、**新しい確認前の版**ができ、修正できる。元の版は残る。
   - 依頼・承認・却下は、監査ログに残す。
6. **提出済みの版は、補正に備えて、記録として残す**：入管から補正を求められたときは、提出した版を残したまま、そこから新しい版を作って修正する（5 の承認が必要）。提出の履歴は、版として並ぶ。

## 実装の順序
1. 本書（方針の記録）。
2. 版の更新方式（確認前の行・保管庫のファイルの上書き）。**実装済み**（`0020_draft_documents_update.sql`、Issue #203）。単位は、案件・文書の種類・出力形式ごとに、最新の確認前の版1つ。確認済み以降が最新の場合は、新しい版を追加する。既存の確認前の版は変更しない。
   ポイント計算表の文書の種類（`hsp_point_sheet`）の追加は、`0021_hsp_point_sheet.sql`（Issue #186）。案件の「ポイント計算表」で「版として保存してダウンロード」を押すと、画面の版とエクセルの版が保存され、以降は上記の版管理に従う。直接ダウンロード（保存しない）も残す。
3. 「最終版」→「提出済み」への変更（DB マイグレーションを含む）。**実装済み**（`0019_document_status_submitted.sql`、Issue #203）。既存の `final` は `submitted` に読み替えた。過去の監査ログの `document_final` は書き換えず、ラベルのみ旧名称として残した。
4. 修正依頼（別 Issue）。

## 未決
- 保管（archived）の版の変更の可否。
- 修正依頼の通知（画面のみか、メール等か）。
- 確認者が退職・不在の場合の扱い（承認は owner・admin が代行できる）。
